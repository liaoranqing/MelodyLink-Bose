## 1. 项目背景

| 项 | 内容 |
|---|---|
| 目标 | 让 **Bose QuietComfort Ultra Earbuds（2代）** 在 OPPO/一加的官方耳机管理 App **Melody**（`com.oplus.melody` 17.6.3）里**原生工作**：识别设备、显示产品图与 3D 模型、三态降噪、抗风噪(CNC)、空间音效、电量 |
| 形态 | LSPosed / libxposed 模块（`compileOnly` libxposed-api 102.0.0，入口 `assets/xposed_init` → `com.melody.melodylink.hook.HookModule`） |
| 测试机 | OPPO Find X8 Ultra（Android 16 / SDK 36），**漏洞临时 root** |
| 由来 | 前任 workbuddy 系列模型做到 2.0.1，2026-10-05 起由 Qoder 接管（token 耗尽交接），已推进到 2.0.12 |
| 用户角色 | 用户本人操作手机与安装 APK，用截图/录屏/logcat 反馈现象；AI 负责取证、改代码、写日志、盯 CI |

**为什么可行**：Melody 的设备能力由「白名单配置（WhitelistConfigDTO）+ 设备目录 + 仓库层 DTO」驱动，UI 只读 DTO/VO 的 getter。把 Bose 伪装成白名单里已有的一款 **OPPO Enco X3（productId `067410`）**，再去 hook 那些 getter/写入方法把值换成我们从 Bose BMAP 协议读到的真实状态，就能不改 APK、不注入新白名单地复用整套 UI。

## 3. 技术选型与决策理由

| # | 决策 | 理由与证据 | 否决过的方案 |
|---|---|---|---|
| 1 | **伪装成白名单已有型号**（Enco X3 `067410`，借用 `colorId 3`） | 宿主对未知型号直接隐藏整片行（`bose.detail.state total=0`）；借现有 profile 可复用全部 UI/图标/布局路径。日志：`mapping registered device ... to sanitized OPPO Enco X3 id=067410` | 自造白名单条目（要改数据库与资源包，风险大） |
| 2 | **剥离 ANC 强度档位**（`copyWithoutAncStrengthModes`） | X3 profile 带 0–10 强度档，Bose 只有三态，留着会渲染出宿主不认识的档位行 | 保留 profile 原样（UI 出错位） |
| 3 | **BMAP 走 RFCOMM channel 2，短会话队列** | Bose 的 ch2 单客户端，A2DP 已占用其他通道；`BoseTransport` 用合并式 worker 串行发会话（0.4.0 曾因每次 tap 递增 generation 丢掉排队中的旧会话，导致只落最后一次） | 长连接（抢占通道、断连不可控） |
| 4 | **乐观完成写入**（`startSonyNoiseWriteFuture` 立即 `complete`） | BMAP 串行队列里可能有电量刷新排在前面，等回执会让宿主 Future 超时报「切换失败」假错 | 等设备 ACK 再返回 |
| 5 | **跨进程用文件式共享状态**（宿主 `getFilesDir()` 下 `.melodylink_*` 一组文件，250 ms 轮询） | Melody 有 `main` 与 `:fg` 两进程，UI 只在 `:fg`，蓝牙栈在 `main`；ContentProvider/广播都不可靠（会被宿主拦截或时序不定）。文件：state/command/cnc/extra 各一对 | Xposed 跨进程对象传递（不可行） |
| 6 | **hook 全部走白名单 `hookNamed`/`hookAny` + `ClassAudit` 上报缺失锚点** | 宿主每次升版 R8 名字就变；`ClassAudit` 在启动时列出本机不再存在的锚点，升级失败可从日志一眼定位 | 反射遍历+模糊匹配（曾导致静默错位） |
| 7 | **UI 刷新=重放宿主自己的绘制回调**，不重绑 Preference | 2.0.9 实锤：`Preference.notifyChanged()` 执行成功但图标不动——图标只由 `NoiseReductionItem.onEarphoneDataChanged(VO)`（详情页）与 `OneSpaceNoisePreference$initObserver$1`（通用设置）绘制 | notifyChanged / notifyDataSetChanged（无效，走过弯路） |
| 8 | **状态镜像 + 索引空间分离**：写入/镜像用**协议索引**（0/1/2），显示用 **modeType**（1/5/2），换算交回宿主 `l9/b.getCurrentNoiseMode(protocolIndex, list)` 反射调用 | 本会话 smali 取证 + 装机日志双向验证：`replayed mode=1 mode_type=5`、`mode=0→1`、`mode=2→2`。自己猜换算表会显示错按钮 | 直接用 `ModeItem.f()` 的整数喂 `ancMode()`（那是 modeType，空间不对，会在通用设置页显示错的高亮） |
| 9 | **模型用宿主自研 `.vfxms` 容器**，不是裸 glb | `ModelScene.loadSceneFromBuffer` 先读 10 个大端 u32 头（config/glb/IBL/skybox/anim 的 start+len）；裸 glb 会把 "glTF" magic 当 configStart 越界，异常被 try/catch 吞掉 → 空白页 | 直接塞 glb（2.0.x 早期踩过） |
| 10 | **去照片 = 保持视图 VISIBLE 但 alpha 钳 0**（hook `View.setAlpha`） | 详情页照片会先闪现再淡出；把宿主注入动画硬改 GONE/INVISIBLE 会连带影响模型加载路径（红鲱鱼，真凶其实是资产 BIN chunk）。alpha 钳制既隐形又不破坏宿主布局逻辑 | 改 visibility（曾致黑屏，2.0.3/2.0.4 已回退） |

## 4. 架构与数据流

### 4.1 进程与职责
- `com.oplus.melody`（主进程）：蓝牙栈、`EarphoneRepository`、`BoseTransport`（BMAP/RFCOMM）、电量与 ANC 回执落库、`writeSharedBoseState()` 发布共享状态。
- `com.oplus.melody:fg`（前台进程）：所有 Activity/Preference UI（`OneSpaceDetailActivity`、详情页 Fragment），只读镜像状态与共享文件。
- **铁律**：持有 View/observer 引用的刷新必须在 `:fg`；写入拦截在主进程。2.0.7/2.0.8 就是栽在把刷新放到了主进程（`:fg` 的 row 锚点在主进程恒 null）。

### 4.2 ANC 一次点击的完整链路（2.0.12 现状）
```
耳机设置(详情页)  NoiseReductionItem$a.c  →[hook nativeNoiseReductionClick]→ dispatchCustomAncWrite
     ├ mirrorAncOptimistically(modeIndex)      # 立刻 acceptAnc 进 bose/sony sessionState
     ├ 主进程: startSonyNoiseWriteFuture → writeSharedBoseState() → refreshTile → BoseTransport.setAncMode
     └ :fg: forwardSonyNoiseWrite(命令文件) → refreshAncRowsAfterWrite()
            → notifyChanged×2 + invokeOnEarphoneDataChanged(VO) + repaintOneSpaceNoiseRow()

通用设置(OneSpace) OneSpaceNoisePreference$a.c → Intent("com.oplus.melody.setgate") → 主进程仓库 s0
     └[hook noiseModeWrite(主进程)]→ 乐观镜像 + writeSharedBoseState()   # 2.0.12 起在拦截时就发布
            → :fg 轮询(250ms) 指纹变化 → applySharedAncMode → repaintOneSpaceNoiseRow()
                   → 反射 getMNoiseReductionModeList / getCurrentNoiseMode / setMCurrentNoiseMode
                   → 反射调 OneSpaceNoisePreference$b.onChanged(VO)   # 唯一能刷新该行高亮的路径
```
绘制路径差异（本次结案的关键）：`OneSpaceNoisePreference` 的高亮**只**发生在其 LiveData observer 内（`$initObserver$1.invoke` 先 `iput` 缓存 VO 再比 `getMCurrentNoiseMode()`），`onBindViewHolder` 完全不碰 `DeviceControlWidget`；而 0585 日志证明宿主 repository publish 不会触发该 observer（26 次 publish、0 次 `onNoiseInfoChange`）。

### 4.3 Hook 清单规模与分类
`HookModule.java` ~7150 行，`hookNamed` 61 处 + `hookAny` 11 组（多候选名），诊断事件 `MLog.event` 116 处。分类：
1. **设备识别/白名单**：`whitelist`、`deviceRegistryGet`、`sonyDetailImage/CardImage`
2. **DTO getter 投影**：`dtoConnectionState/AclState/SupportSpp/InitCompleted/NoiseReductionMode`、`detailInfo*`（v9.a / G9.a）、`noiseReductionModeVO`（pa.C1405p / Ba.z）、`opsNoiseReductionMode`
3. **写入拦截**：`noiseWrite`（U.L0 / J.o0）、`noiseModeWrite`（U.s0 / J.v0）、`noiseModeWriteClient`、`stateCallback`、`repositoryNotify/Get/Observe/DtoBuild`
4. **UI 注入与保活**：`detailPreferenceAdd`、`onespaceNoiseBind`、`noiseReductionItemDataChanged`、`nativeNoiseReductionClick`、`oneSpaceNoiseObserver`(2.0.12)、`onespaceNoiseMenuCheck/SwitchShow`、`detailSetVisibility`、`boseHeaderShowAnimationEnd`、`detailActivityFinish/AfterTransition`
5. **资产替换**：`sonyCardBind/CardImage`（2D 图）、`sonyDetailImage/Placeholder`（3D 模型与 `.vfxms` 长度）
6. **磁贴桥**：`BoseControlProviderBridge` hook `com.oplus.melody.provider.EarphoneControlProvider.query` 并 `notifyChange`

## 8. 已知问题与注意事项（含硬禁忌）

**硬禁忌（违反会造成不可逆损失）**：
1. **严禁 `adb reboot` 或任何重启手机**：该机是漏洞临时 root，重启后 root 失效且极难再取得。
2. **不本地编译 APK**：本机无 Android SDK；构建只走 GitHub Actions。
3. **源码文件严禁用 Windows PowerShell 的 `Get-Content`/`Set-Content` 读写**：GBK 往返曾把中文注释毁成乱码并打挂 CI。只用编辑工具或 UTF-8 安全的管道。
4. **反编译产物绝不提交/上传**：smali、dex、APK、dexdump 全文都是 OPPO 版权物（连带的 `.vfxms` 参考容器 `detail_model.vfxms` 亦属 OPPO）。可以上传的是**事实性接口信息**（类名/方法名/hook 对照表）与我们自己的代码。
5. **AI 不代推、不代下载需凭据的 artifact**：push 由用户侧工具自动完成；token 不由 AI 取用。
6. **每次改动必须递增 `versionCode`/`versionName`**（装机验证与日志对齐全靠它）。

**易错点（做过一遍的弯路，别再走）**：
- 模型黑屏 ≠ 视图可见性问题：**先字节级校验 `.vfxms`**（10 个大端 u32 偏移自洽、glb BIN type=`0x004E4942`、切片长度=头声明值、KTX magic），再用 `uiautomator dump`（`MSYS_NO_PATHCONV=1`）确认 TextureView 在位且尺寸正常。
- 刷新 UI 要挑对**进程**（`:fg`）和挑对**函数**（宿主的绘制回调，不是 Preference rebind）。
- 宿主有两套 ANC UI 类，索引空间还不一样（协议索引 vs modeType）。
- 反编译目录里同名类分散在多个 dex 拆分目录（`smali1/smali2/s1dto/s2c9/s2dto`），且 Windows 大小写不敏感导致 `l9/b` 实际落在 `l9.1/b.smali`——别按路径名断定类名。
- `MLog.event` 打印的 `process=` 字段（来自 `LSPosedFramework` 行）是判定进程归属的唯一可靠手段。

## 9. 方法论：本项目改一个 bug 的标准闭环

1. **先恢复上下文**：`opslog/STATUS.md` → `opslog/README.md` → `opslog/当月.md` 最新若干 Entry → `HANDOFF.md` →（需要历史）`.workbuddy/memory/`。
2. **取证，不猜**：现场 logcat（`adb logcat -d -b all`）、截图/录屏抽帧（OpenCV 可用）、`uiautomator dump`、smali 静态核对（读点击/绘制链，不止读方法名）、必要时字节级校验资产。
3. **小步实现 + 诊断先行**：新逻辑必须自带可判定的事件（如本轮的 `bose.anc.onespace.replayed/skip/replay_fail`），让下一次实测能直接区分「没捕获到」/「映射不上」/「反射失败」。
4. **静态闸**：`python static_check.py`（原始类型比 null、括号平衡）。本机无 JDK 时，用 node 做同样的括号/花括号平衡并与 `git show HEAD:` 的旧版逐对计数比对（本会话即用此法验证 `{}`/`()`/`[]` 与 HEAD 一致）。
5. **提交即发布**：commit → 用户侧自动 push → CI（缓存后约 1–2 min）→ 用 `api.github.com/repos/.../actions/runs` 核实 `conclusion=success`。
6. **装机复验 + 双向核对**：`dumpsys package com.melody.melodylink` 确认版本，再看事件是否按预期出现/计数。
7. **写日志**：五要素 Entry（含「调用了什么方法」「查到的实锤」「失败与结论」「下一任动作」），必要时重写 `STATUS.md`，更新 `HANDOFF.md`/`docs/`，把可复用的教训落进记忆。

## 附录 A：`make_vfxms4.py`（资产打包脚本全文，2.0.6 修复版）

```python
import sys, struct, json
sys.stdout.reconfigure(encoding='utf-8')

# 2.0.3 asset: whiten the Moonstone materials (glb shipped them as light-blue
# baseColorFactor [0.434,0.68,1.0] with no texture -> the product/case interior
# rendered blue), and enlarge (modelScale 1.25 -> 1.5). Same X3 config/IBL/skybox.
X3  = r'<workspace>/bose3d/detail_model.vfxms'          # OPPO 版权，本地参考容器
GLB = r'<other workspace>/bose3d/Bose_QCUE2_模型/Bose_QCUE2_通用.glb'
OUT = r'<workspace>/bose3d/bose_qcue2_v4.vfxms'

MODEL_SCALE = 1.5
IBL_INTENSITY = 18000
BLOOM = False
WHITE = [0.92, 0.92, 0.92, 1.0]   # neutral off-white for the "Moonstone" parts

# --- 1. edit glb materials ---
glb = bytearray(open(GLB,'rb').read())
assert glb[:4]==b'glTF'
jlen = struct.unpack('<I', glb[12:16])[0]
gltf = json.loads(bytes(glb[20:20+jlen]).decode('utf-8'))
changed=[]
for m in gltf.get('materials',[]):
    nm=m.get('name','')
    if 'Moonstone' in nm:
        pbr=m.setdefault('pbrMetallicRoughness',{})
        if pbr.get('baseColorFactor') is not None:
            pbr['baseColorFactor']=WHITE; changed.append(nm)
print('whitened materials:', changed)
newjson=json.dumps(gltf, separators=(',',':'), ensure_ascii=False).encode('utf-8')
newjson+=b' '*((4-len(newjson)%4)%4)
# BIN chunk header is at [20+jlen : 20+jlen+8] = (binlen, bintype); data follows.
# (v4 bug: read binlen from 20+jlen+8 = inside bin DATA, and copied data without the
#  8-byte header -> garbage BIN chunk -> glTF parse fail -> black model.)
binlen=struct.unpack('<I', glb[20+jlen:20+jlen+4])[0]
bintype=struct.unpack('<I', glb[20+jlen+4:20+jlen+8])[0]
assert bintype==0x004E4942, 'BIN chunk type wrong: %x'%bintype
binchunk=bytes(glb[20+jlen:20+jlen+8+binlen])
outglb=bytearray(glb[:12])
outglb+=struct.pack('<II', len(newjson), 0x4E4F534A)+newjson
outglb+=binchunk
struct.pack_into('<I', outglb, 8, len(outglb))
print('glb %d -> %d'%(len(glb),len(outglb)))

# --- 2. config ---
x3=open(X3,'rb').read()
u32=lambda o: struct.unpack('>I', x3[o:o+4])[0]
cs,cl,gs,gl,is_,il,ss,sl,*_= [u32(i) for i in range(0,40,4)]
cfg=json.loads(x3[cs:cs+cl].decode('utf-8'))
cfg['modelScale']=MODEL_SCALE
cfg.setdefault('light',{})['iblIntensity']=IBL_INTENSITY
cfg['enableBloom']=BLOOM
cfg_bytes=json.dumps(cfg,ensure_ascii=False,separators=(',',':')).encode('utf-8')

# --- 3. repack ---
ibl=x3[is_:is_+il]; sky=x3[ss:ss+sl]
h1=40+len(cfg_bytes)
header=struct.pack('>10I',40,len(cfg_bytes),h1,len(outglb),h1+len(outglb),len(ibl),h1+len(outglb)+len(ibl),len(sky),0,0)
out=header+cfg_bytes+bytes(outglb)+ibl+sky
open(OUT,'wb').write(out)
print('written',OUT,len(out))

u32o=lambda o: struct.unpack('>I', out[o:o+4])[0]
v=[u32o(i) for i in range(0,40,4)]
c=json.loads(out[v[0]:v[0]+v[1]].decode('utf-8'))
assert c['modelScale']==MODEL_SCALE and c['light']['iblIntensity']==IBL_INTENSITY and c['enableBloom'] is False
assert out[v[2]:v[2]+4]==b'glTF'
# verify glb material whitened
gj=struct.unpack('<I', out[v[2]+12:v[2]+16])[0]
g=json.loads(out[v[2]+20:v[2]+20+gj].decode('utf-8'))
assert all(mm['pbrMetallicRoughness'].get('baseColorFactor',[1,1,1,1])[2]<0.95 for mm in g['materials'] if 'Moonstone' in mm.get('name','') and mm['pbrMetallicRoughness'].get('baseColorFactor'))
assert out[v[4]:v[4]+8]==b'\xabKTX 11\xbb' and out[v[6]:v[6]+8]==b'\xabKTX 11\xbb'
assert v[2]==40+v[1] and v[4]==v[2]+v[3] and v[6]==v[4]+v[5] and v[6]+v[7]==len(out)
print('self-check OK; BOSE_MODEL_LENGTH =', len(out))
```

> 注：脚本里的绝对路径已替换成 `<workspace>` 占位；实际值见 §5 工作区结构。
